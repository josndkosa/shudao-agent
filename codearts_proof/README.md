# codearts_proof/ —— 华为云码道使用证明材料

赛题要求：「作品开发过程**必须**使用华为云码道（AI Coding 工具）作为核心 AI 编程工具，并提交码道使用痕迹证明材料」，
评分细则「码道深度使用 25 分」的三个评审点：
1. 码道在开发**全流程**的覆盖度（环境搭建、代码生成、调试排错、文档生成）
2. **Prompt 设计质量**与工具使用效率
3. 使用证明材料的**完整性与真实性**

本目录就是这 25 分的载体。

## 目录内容

| 文件/目录 | 对应评分点 |
|---|---|
| `prompts/_已执行/` | ★ **已执行过的任务单原文，逐份归档**（00–04 全轮次 + 03E/03F/03G/03H/03I/03J/05/03K 等；清单以该目录实际内容为准，份数不在文档里写死）——② Prompt 设计质量 + ① 覆盖度的**原始素材** |
| `debug-log-2026-10-28.md` | ★ **完整调试排错过程记录（十七轮）**——含"工程反思"，是「码道深度使用」最硬的一份证据 |
| `07-在线模式实测/` | ★ DeepSeek 在线实跑输出存档（含 SHA-256 与生成命令）——「AI 真的在工作」的铁证文本 |
| `ACCEPTANCE.md` | 全局验收标准与风险登记 |
| `回贴模板.md` | 与码道协作的闭环协议 |
| `zip-layout.md` | ③ 提交包结构与提交规范 |

## 需要你自己补的截图目录（按编号，每类至少 2 张）

```
01-环境搭建与工程初始化/       venv、依赖安装、.env 配置、目录结构
02-代码生成-三段式管线/         prompt 输入 + 码道输出（pipeline/planner/validator）
03-代码生成-前端可视化/         prompt 输入 + 码道输出（static/）
04-调试排错-跨城日时长规则误报/  ★ 最关键：真实排错过程（定位口径不一致 → 修 → 测试转绿）
05-文档生成-PPT与readme/        Space 模式生成 PPT / readme 的过程
06-一键安装与部署验证/          install.sh / start_server.sh 的真实运行输出与提交记录截图
```

> `07-在线模式实测/` 已由工程侧产出（在线 CLI 输出存档），不是截图目录；
> 人工提交记录的截图并入 `06-`。

## 纪律

- **真实性是评分项**。截图必须是真实交互记录，不要拼图、不要美化、不要伪造日志。
- 人工修改过的部分，在 `readme/README.md` 的「码道应用总结」里如实说明。
- 每次用完码道立刻截图归档——这是最容易丢、也最容易得的分。

## 使用流程

1. 打开 `prompts/` 里对应编号的文件（**已执行过的都在 `_已执行/`，不再重复执行**），**整段复制**给码道
2. 码道执行完，把**输入的 prompt + 码道的完整回复 + 改动摘要**截图，按上面的编号存进对应目录
3. 按该 prompt 末尾的「交付要求」逐条验收
4. 全局验收走 `ACCEPTANCE.md`
5. 打包规则走 `zip-layout.md`（**`_已执行/` 里的全部 prompt 原文要一并提交**——
   `scripts/package.py` 的 `need_prompts` 清单会逐一校验，缺了打包阶段就报错）
