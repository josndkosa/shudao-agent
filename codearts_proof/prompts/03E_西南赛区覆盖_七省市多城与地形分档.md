## 一、为什么改成西南赛区覆盖（先把立论说清楚）

赛题原文（`docs/赛题情报/tab_introduction.txt`）对西南赛区的定义：

> **西南赛区包含：四川、重庆、云南、贵州、广西、海南、西藏**

也就是说，"覆盖西南"**不是我们自选的叙事，而是直接对齐赛题自己的赛区划分**。
评分细则「专业贴合与创新 25 分」第 1 条是「作品是否贴合**本专业**实际需求，落地合理性」，
第 3 条是「是否体现**专业特色与行业洞察**」——地域贴合正是这一栏的主战场。

对比"全国 40 城"：
- 覆盖西南七省市 → **正好是赛题定义的赛区**，论证是正的
- 覆盖全国 → 反而稀释了西南的地域故事
- 成本：40 城 ≈ 6 天；西南 15 城 ≈ **3.5–4 天**，省下的 2 天留给 PPT / 视频 / 留痕归档

**结论：西南赛区覆盖 = 更正、更省、更对。**

## 二、但"西南"不能只是"多几个城市"——必须做出**西南专属的差异化**

如果只是把成都重庆的 POI 复制 15 遍，那只是"数量变多"，不是"洞察变深"。
西南真正的独特性是**四个真实维度**，每一个都必须**落到数据字段与规则参数上**：

| 维度 | 西南的具体性 | 落点 |
|---|---|---|
| **立体地形** | 重庆洪崖洞爬百米、贵州梯田、峨眉山陡升 | `slope` 字段在西南**才有区分度**（平原城市全是 0） |
| **高原** | 昆明 1890m、拉萨 3650m | 同为"强度 8.5"，昆明与成都的体感完全不同 → **强度阈值按地形分档** |
| **民族与节庆** | 苗族/白族/壮族/藏族，泼水节、三月三 | 标签体系扩展（民族、节庆、歌舞、纹样） |
| **气候带** | 海南热带雨林 / 云南高原 / 四川盆地 / 西藏高原 | 同一周内温差极大 → 天气快照必须按城给 |

### ★ 关键设计：规则阈值**按地形分档**（这是本条最有价值的产出）

现在 `validator.py` 里 `INTENSITY_CAP = 8.5` 是**硬编码全局常量**。
西南的真实情况是：**同样的"强度 8.5"，在成都只是多走点路，在昆明是在 1900 米高原上走，在拉萨是在 3650 米高原上走。**

所以把强度阈值改成**按城市地形分档**：

```python
# server/data/meta.json 里每个城市带：
"terrain": {
  "type": "basin",        # plain | basin | hill | karst | plateau | alpine | tropical
  "intensity_cap": 8.5,  # 该地形下的日强度上限
  "alt_m": 500           # 海拔（米），可选
}
```

| terrain | 典型城市 | intensity_cap | 依据 |
|---|---|---|---|
| `basin` | 成都 | **8.5** | 盆地平原，基准不变 |
| `plain` | 南宁、海口 | 8.5 | 平原 |
| `hill` | 桂林、乐山 | **8.0** | 丘陵/喀斯特，坡度普遍偏高 |
| `karst` | 贵阳、荔波、安顺 | **7.5** | 喀斯特地形连续爬升 |
| `plateau` | 昆明、贵阳 | **7.0** | 高原，氧耗与体感负担更高 |
| `alpine` | 拉萨、林芝 | **6.0** | 高原极高海拔（3650m） |
| `tropical` | 三亚、西双版纳 | **8.0** | 湿热环境下体力消耗更快 |

**这一步同时带来三个收益：**

1. **差异化创新点（25 分）**：一条"按地形自适应"的规则，是全国通用方案给不出的
2. **架构稳定性（15 分）**：规则引擎从"硬编码常量"升级为"**参数化 + 配置驱动**"——
   这是"架构合理"的最好证据，比"数据量大"强得多
3. **数据自洽**：西南的高 `slope` 值不再触发一堆"误报"，而是**由地形配置解释**

> **V1（时长）、V2（开放窗口）、V4（预算）、V5（亲子）四条规则不随地形变化**，只有 V3 强度分档。
> 这个"**哪些规则该参数化、哪些不该**"的判断本身也要写进文档，是设计取舍的体现。

## 四、数据格式与质量（**最贵的一块**）

### 目录（沿用 Prompt 04 的数据分层）

```
server/data/
├── schema.md              ← 字段规范（补充"多城"与"terrain"章节）
├── meta.json              ← ★ 城市总表（含 terrain 分档、weather、hub、tags_extra）
├── cities/
│   ├── 成都.json  重庆.json  昆明.json  大理.json  贵阳.json  桂林.json
│   └── 乐山.json  阆中.json  丽江.json  西双版纳.json  安顺.json
│       西江千户苗寨.json  北海.json  三亚.json  拉萨.json
└── providers/
    └── ota_sample/        ← OtaProviderStub 用的模拟 OTA 响应（字段名与本地 schema 不同）
```

### 单城文件格式（与现有 `pois.json` 一致）

```jsonc
{
  "city": "贵阳",
  "pois": [
    {
      "id": "GY-01", "name": "甲秀楼", "city": "贵阳",
      "lat": 26.5700, "lng": 106.7100,
      "tags": ["历史文化", "建筑", "民族"], "ticket": 0, "visit_hours": 1.5,
      "open_hour": [7, 22], "reserve": 0, "crowd_peak": [10, 16],
      "crowd_level": 3, "slope": 1, "family": 4,
      "night_friendly": false, "must_see": true,
      "summary": "……一句话，具体、有信息量，不要模板腔"
    }
  ]
}
```

### 硬质量要求

- **13 个字段全部填写**，不允许留默认值、不允许用 `0` 糊弄
- **`open_hour` 必须符合真实作息**，且**各城各点不得雷同**
  （博物馆 9–17、公园 6–21、夜市 19–24、观景台 9–23、山寺 8–17……）
- **`slope` 要体现西南的地形**：
  - 盆地（成都）：0–1
  - 丘陵/山城（重庆、乐山、大理、桂林）：1–3，**重庆的点普遍 2–3**
  - 喀斯特（贵阳、安顺、西江、荔波）：1–3
  - 高原（昆明、丽江、拉萨）：1–2，**且 `alt_m` 要体现高原**
  - 滨热带（三亚、西双版纳、北海）：0–1
- **`night_friendly`**：夜景/夜市/夜游类为 true（这是"夜游成渝/夜行大理"的叙事落点）
- **`must_see`**：每城 2–3 个真正必去的地标
- **`summary`**：**每点都要写**，写特色不写套话
- **`tags` 要扩展西南专属维度**：民族（苗/白/壮/藏/彝）、节庆（泼水节/三月三/火把节）、
  地质（喀斯特/丹霞/雪山/梯田/海蚀）、地貌（梯田/峡谷/溶洞）
- **`id`**：城市拼音缩写 + 序号（`GY-01`、`LZ-03`、`SY-02`…），全局唯一
- **门票**：贴近真实（免费 / 几十元为主）

> ❌ **不要用程序批量生成 `summary` / `open_hour` / `tags`**——那会立刻露馅。
> 可以程序生成骨架（id、经纬度、名称列表），**厚字段必须逐条填**。

### 批次编排（每批都可交付）

```
批次 1：成都 重庆 昆明 大理 贵阳 桂林          （深度层 6 城）★ 优先级最高
批次 2：乐山 阆中 丽江 西双版纳 安顺
批次 3：西江千户苗寨 北海 三亚 拉萨             （广度层剩余）
```

每批完成 → 导出资产 → `pytest` → `git commit`（message：`feat(data): 新增 N 城 POI 快照与地形分档 [prompt 03E batch N]`）。
**时间不够，停在任何一批都是完整可交付的状态。**

### 任务 C：城际交通自动生成（**不要手写 105 条矩阵**）

替换 `route.py` 里硬编码的 `INTERCITY_RAIL`：

```python
def intercity(city_a, city_b):
    """按两城枢纽球面距离自动生成城际交通时长与票价。"""
    d = haversine(hub_a["lat"], hub_a["lng"], hub_b["lat"], hub_b["lng"])
    hours = clamp(1.2 + d / 250.0, 1.2, 14.0)
    # 西南长途（川渝黔→桂/琼/藏）明显更长：跨省加权
    if {a["province"], b["province"]} & {"西藏", "海南", "广西"} and a["province"] != b["province"]:
        hours *= 1.25
    price = round(clamp(d * 0.48, 60, 2200) / 10) * 10
    return {"hours": round(hours, 2), "price": price, "km": round(d)}
```

- **保留** `INTERCITY_RAIL` 作为人工覆盖表（自动生成为默认值）
- 成都–重庆 ≈ 268km → 时长 ≈ 2.3h，票价 ≈ ¥130（与现有基线接近，偏差要在 CHANGELOG 说明）
