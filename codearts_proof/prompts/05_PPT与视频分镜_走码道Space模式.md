### 第 2 页 · 场景分析（痛点）

文旅行程规划的三个真实痛点：

1. 开放时间 / 预约 / 人流高峰信息分散，靠人肉查
2. 重庆立体地形 → 爬坡强度与体力分配被忽略，日程排到晚上 21 点还在爬坡
3. 亲子出行需要"强度可控 + 开放窗口匹配"，人工排几乎必然踩坑

一句话结论：**问题不在"能不能生成行程"，而在"生成的行程靠不靠谱、能不能解释"**

（这一页立的是靶子，后面所有页面都在回应它 —— 别写成罗列痛点就完事。）

### 第 3 页 · 场景分析（为什么是西南赛区 + 高校组）

- 地域贴合：**赛题原文对西南赛区的定义 = 四川、重庆、云南、贵州、广西、海南、西藏** ——
  我们的数据层**直接对齐这个赛区划分**，不是自选的叙事
- 高校组贴合：**定位为高校 AI Agent 课程的实训 / 示范项目** —— 换一组 POI 快照就能复现到
  其他城市、其他学科（"用同一条管线做实验室开放日导览""做城市非遗路线"）
- 教育实践价值：完整展示"AI Coding → 工程化交付"的闭环，学生可以照着跑通

### 第 4 页 · 方案设计 · 整体架构（mermaid 图）

```
flowchart TD
  A[用户输入 天数/预算/偏好/城市] --> B[规划段 Planner]
  B --> C[校验段 Validator 纯规则 V1-V5]
  C -- 违规清单回流 最多3轮 + 收敛检测 --> B
  C -- 零违规 --> D[叙事段 Narrator]
  D --> E[EventBus 事件流 每条带 reason]
  E --> F[前端 分城 SVG 路网图 + 逐日时间轴]
  E --> G[可倒带决策回放]
```

三个要点：三段职责单一、各段可独立单测、事件流是**一等公民**（贯穿全流程）

⚠️ 这张图里**只画一次管线** —— 在线模式现在也只跑一次（Prompt 03H 消除了双跑），
行程和事件流同源。

### 第 5 页 · 方案设计 · 为什么不是"多 Agent 框架"

- 一个 Function Calling 循环 + 角色切换，包装成"多 Agent"经不起架构追问
- 三段式管线：每段独立可测、离线可跑、规则可审计 —— **更诚实的工程表达**
- 落点：赛题"技术架构与工程质量"15 分里的"代码结构规范性、可维护性"

### 第 6 页 · 方案设计 · 数据层

- **本地 POI 厚字段快照**：开放时段 / 预约难度 / 人流高峰 / **爬坡强度** / 亲子友好度 /
  夜间体验 / 建议游玩时长
  —— ⚠️ **具体城数和 POI 数请从 `server/data/` 和 `/api/meta` 实时读，不要写死数字**
- **决策依据从"一个分数"变成"一组可解释的硬约束"**
- 声明：赛题版本用本地快照保证演示稳定，数据层可对接 OTA 开放接口（接口边界已预留）
- 加分点：**新增城市零代码改动**（放一个数据文件 + `meta.json` 登记就行，
  `load_city_pois` 已经改成自动索引了）

### 第 7 页 · 核心功能 · 规划段

- 偏好打分 → 多城按候选池分数比例分天 → 逐日贪心装箱 → 最近邻排序（夜间点压轴）→ 时间线推算
- 每一步都发**带 reason 的事件**，前端可回放

⚠️ 别说"两城" —— 已经支持多城分天了（默认演示仍是成渝 3 天，但规划器按候选池分数比例分天）。

### 第 8 页 · 核心功能 · 校验段（五张规则表）

| 规则 | 含义 | 阈值 | severity |
|---|---|---|---|
| V1 | 日时长 / 收班时间 | 08:30–22:00，跨城日容量扣城际时长 | hard |
| V2 | 开放窗口 | 到离时间须落在 POI 开放时段内 | hard |
| V3 | 体力强度 | Σ(slope + crowd×0.4) ≤ **按地形分档**（盆地 8.5 / 丘陵 8.0 / 喀斯特 7.5 / 高原 7.0 / 高原极高 6.0 / 热带 8.0） | **soft** |
| V4 | 预算 | 门票+餐饮+交通 ≤ 请求预算 | hard |
| V5 | 亲子友好 | 排除亲子友好度 < 2 的点 | hard |

- **违规清单自动回流规划段，最多 3 轮定向修复 + 收敛检测**（同一违规集不变就停）
- 强调：**校验段零 LLM，纯规则可审计**

**软硬分级是这一页最值钱的地方，别只列阈值：**
V3 强度没有唯一正确的删点解 —— 系统如实提示、把决策权交还用户，**不自动删点**
（自动删会误伤必游地标和夜景压轴点）。
另外**地形分档**：同样的"强度 8.5"，在成都只是多走点路，在高原是在海拔上走，
所以阈值随地形收紧（这是"因地制宜"的规则参数化，不是写死的常量）。
