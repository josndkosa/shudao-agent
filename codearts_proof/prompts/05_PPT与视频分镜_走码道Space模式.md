## 二、逐页清单

### 第 1 页 · 封面
- 标题：**蜀道智行 —— 成渝行程规划智能体**
- 副标题：*规划 → 校验 → 叙事 的三段式管线，把 Agent 的决策过程做成可回放的产品*
- 占位行（**不要编造，保留 `______` 由参赛者手填**）：

### 第 2 页 · 场景分析（痛点）
- 文旅行程规划的三个真实痛点：
  1. 开放时间/预约/人流高峰信息分散，靠人肉查
  2. 重庆立体地形 → 爬坡强度与体力分配被忽略，日程排到晚上 21 点还在爬坡
  3. 亲子出行需要"强度可控 + 开放窗口匹配"，人工排几乎必然踩坑
- 一句话结论：**问题不在"能不能生成行程"，而在"生成的行程靠不靠谱、能不能解释"**

### 第 3 页 · 场景分析（为什么是西南赛区 + 高校组）
- 地域贴合：成渝文旅是西南赛区的真实需求，赛题明确鼓励"贴合地域文化"
- 高校组贴合：**定位为高校 AI Agent 课程的实训/示范项目**——换一组 POI 快照即可复现到其他城市/其他学科（如"用同样管线做实验室开放日导览""做城市非遗路线"）
- 教育实践价值：完整展示"AI Coding → 工程化交付"的闭环，学生可照着跑通

### 第 4 页 · 方案设计 · 整体架构（**mermaid 图**）
```
flowchart TD
  A[用户输入 天数/预算/偏好/亲子] --> B[规划段 Planner]
  B --> C[校验段 Validator 纯规则 V1-V5]
  C -- 违规清单回流 最多3轮 --> B
  C -- 零违规 --> D[叙事段 Narrator]
  D --> E[EventBus 事件流 每条带 reason]
  E --> F[前端 SVG双城路线图 + 逐日时间轴]
  E --> G[可倒带决策回放]
```
- 三个要点：三段职责单一、各段可独立单测、事件流是**一等公民**（贯穿全流程）

### 第 5 页 · 方案设计 · 为什么不是"多 Agent 框架"
- 一个 Function Calling 循环 + 角色切换，包装成"多 Agent"经不起架构追问
- 三段式管线：每段独立可测、离线可跑、规则可审计 —— **更诚实的工程表达**
- 落点：赛题"技术架构与工程质量"15 分里的"代码结构规范性、可维护性"

### 第 6 页 · 方案设计 · 数据层
- 40 个 POI 厚字段快照：开放时段 / 预约难度 / 人流高峰 / **爬坡强度** / 亲子友好度
- **决策依据从"一个分数"变成"一组可解释的硬约束"**
- 声明：赛题版本用本地快照保证演示稳定，数据层可对接 OTA 开放接口（接口边界已预留）

### 第 7 页 · 核心功能 · 规划段
- 偏好打分 → 两城按候选池分数比例分天 → 逐日贪心装箱 → 最近邻排序（夜间点压轴）→ 时间线推算
- 每一步都发**带 reason 的事件**，前端可回放

### 第 8 页 · 核心功能 · 校验段（**五张规则表**）
| 规则 | 含义 | 阈值 |
|---|---|---|
| V1 | 日时长 / 收班时间 | 08:30–22:00，跨城日容量扣 1.8h |
| V2 | 开放窗口 | 到离时间须落在 POI 开放时段内 |
| V3 | 体力强度 | Σ(slope + crowd×0.4) ≤ 8.5 |
| V4 | 预算 | 门票+餐饮+交通 ≤ 请求预算 |
| V5 | 亲子友好 | 排除亲子友好度 < 2 的点 |
- **违规清单自动回流规划段，最多 3 轮定向修复**
- 强调：**校验段零 LLM，纯规则可审计**

### 第 9 页 · 核心功能 · 叙事段 + 断网保命
- 在线 LLM 文案 / 离线模板兜底，`SD_LLM_MODE` 三态开关
- **答辩现场断网也能完整演示**（这是刻意设计的工程决策，不是妥协）

### 第 10 页 · 核心功能 · 可倒带决策时间轴（**差异化王牌，单独成页**）
- 痛点：Agent 的决策过程通常是黑盒或滚动日志，看完就没了
- 本作品：每个决策带 `reason`，前端做成**可拖动、可回放的决策时间轴**
- 回答评委必问的那句：**"为什么第二天排这三个点？"**
- 配图：右侧回放器 UI 截图（从前端截）

### 第 11 页 · 核心功能 · 对话式改行程
- 输入"第二天太赶" → 只重排那一天（容量收紧 → 重选 → 重建时间线 → 规则复查）
- 事件流记录用户介入全过程 → 回放时间轴出现"第二幕"
- 关键设计：**时间线计算始终在本地**，LLM 只负责意图与顺序，不负责编时间

### 第 12 页 · 核心功能 · 可视化
- 双城 SVG 自绘路线图（成渝各一幅，避免 250km 尺度下点位挤压）+ 高铁跨城连线
- 按天着色 / 路径描绘动效 / 点位详情 / 负载与预算条
- **零构建、零外链、零 CDN**

### 第 13 页 · 创新亮点（**四个点，逐条一句话**）
1. **决策过程即产品**：把 Agent 的 reason 变成可回放的可视化资产，而不是日志
2. **规则引擎做校验**：LLM 产出 + 纯规则校验 + 违规回流修复，"智能"与"可靠"分离
3. **厚字段本地快照**：断网保命 + 决策依据可解释，一举两得
4. **双城 SVG 自绘**：不依赖任何地图服务，跨城尺度问题用"分城投影"解决
