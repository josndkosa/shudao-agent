## F1（必改）：`main.js` 的 `revise()` 有 off-by-one，第二幕的"用户介入"事件没生效

```js
const cut = state.events.findIndex(e => e.stage === "revise");
state.player.seek(cut >= 0 ? cut : res.timeline.length - fresh.length);
```

`player.seek(k)` 的语义是「**前 k 条已生效**」，当前高亮行是 `this._rows[this.cursor - 1]`
（见 `player.js` 的 `seek()`）。

divider 事件（`stage === "revise"`）在数组里的 0-based 下标是 `cut`。
要让 divider **本身生效**，必须 `cursor = cut + 1`。现在传的是 `cut`，**divider 差一位没生效**。

**现象**：改完行程后，界面停在"改之前"的画面，用户看不到"用户介入"这一拍。

**改法**：`seek(cut >= 0 ? cut + 1 : ...)`。

顺带修一个闪烁：`revise()` 里现在是
```js
state.player.setEvents(res.timeline);   // 内部会 seek(this.cursor)（旧 cursor）
...
state.player.seek(cut + 1);
```
`setEvents` 先按旧 cursor 渲染一次旧画面，再跳到目标，会闪一下。
**先算好目标 cursor，再一次性 setEvents + seek。**

## F2（必改 · 核心卖点）："违规回流修复"在地图上看不见——被摘掉的点仍然亮着

这是**最重要的一条**。

「规划 → 校验 → 违规回流修复 → 复检通过」是本作品的核心卖点，
但当前前端只做了「事件列表里的文字」，**地图和行程卡没有体现修复动作**：

- `main.js` 的 `applyEvent` 对 `type === "fix"` 只做 `view.fixes.push(ev)`——**存下来但没用**
- `map.js` 的 `render()` 里，被修复移除的点**依然显示为已揭示的亮点**
- 演示时评委看到的是：地图上 4 个点全亮着 → 事件流说"移除 磁器口" → **地图上磁器口还在**

### 要求

**（1）后端侧（`server/agent/planner.py` 的 `fix()`）——只加字段，不改逻辑**

在 `fix()` 发出的每条 `plan/fix` 事件的 `detail` 里带上被移除的 POI id：

```python
bus.emit("plan", "fix", f"第{v['day']}天移除 {target.get('name')}",
         reason=f"触发{v['rule']}：{v['detail']}", violation=v["rule"],
         removed=[target.get("poi_id")])     # ← 新增
```

V1/V2/V4 三条分支都要带 `removed=[...]`（V3 现在是 soft，不进 fix）。

**（2）前端侧**

- `main.js` 的 `applyEvent`：处理 `type === "fix"` 时，把 `ev.detail.removed` 里的 id
  记进 `view.removed.get(day)`（已有这个 Map 的雏形，`map.js` 的 `render()` 里已经在读 `removed`，但**从来没人往里写过**）
- `map.js` 的 `render()`：被 `removed` 命中的 marker 要**变灰 + 打叉**（不要直接消失——
  消失会让人以为数据丢了，打叉才表达"被规则否决"）
- `timeline.js` 的行程卡：被移除的点用删除线 + 灰字 + 一个小标记（如 `✕ 被规则移除`）呈现

**（3）要能看到「复检通过」**

修复后重新校验会发 `validate/pass`。事件流里 `violation → fix → pass` 三条连起来，
地图上那个点从"亮"变"灰叉"，再出现"校验通过"——**这一串就是本作品的解题过程，视觉上必须成立。**

## F3（必改）：`MockApi.revise()` 的 `revised_day` 硬编码为 2

```js
return { itinerary: revised.itinerary, timeline, revised_day: 2, message: "..." };
```

`demo-revised.json` 是 `--days 3 --budget 1200 --tags 美食` 的产物，**城市分配未必和主 demo 一样**，
"第 2 天"是猜的。

**改法**：从两份行程里算出**实际变化的那一天**（对比每天的 `items` 里的 `poi_id` 集合，
找出差异最大或不同的一天），返回它的 `day`；若完全相同则返回 `null`。
前端 `timeline.js` 应据此高亮那一天。

## F4（小改）：`map.js` 的浮层开放时间显示错误

```js
`<div class="t-row">门票 ${...} · ${p.open_hour[0]}:00-${p.open_hour[1]}:00</div>`
```

`open_hour` 是小数小时，`[8, 18.5]` 会显示成 **"8:00-18.5:00"**。
请写一个小格式化函数：`18.5 → "18:30"`、`9 → "09:00"`、`24 → "24:00"`。

## F5（建议改）：流式推进期间，播放器状态不明确

现在 `api.stream()` 在实时推事件的同时，`main.js` 每条都调 `renderAll(state.events.length)`——
**界面自动跟随最新事件**。但用户此时若点"播放"，`player.cursor` 会独立前进，
**两套时间线打架**（cursor 指向的事件 ≠ 刚到达的事件），视觉上会跳。

**改法（任选其一，推荐第一个）**：
1. **流式期间给播放器加"实时跟随"态**：禁用播放/单步/拖动，把进度条置灰并显示「实时接收中…」；
   流结束后自动启用，播放器转为"可回放"态，徽标从「实时」切成「可回放」
2. 或者：流式期间用户若手动 seek，则**停止自动跟随**（不再被新事件拽走），并显示"已脱离实时"
