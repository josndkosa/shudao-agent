## 一、这批活儿要解决什么

代码侧已经到边际收益很低的地方了——132 个测试、冒烟 23 步、CI 三连、在线幻觉治理过两轮。
剩下的风险不在功能，在**三件"说明不了"的事**：

**第一件，数字自己打自己。** 现在同一件事在不同文件里是四个值：根 `README.md` 徽标 79 passed、
`ACCEPTANCE.md` 写 96 个测试、`视频分镜.md` 和 `gen_ppt.py` 写 133、`CHANGELOG` 最新一条写 132；
POI 一处写 6 城 101 点、一处写 15 城 237 点；任务单一处 14 份、实际归档 18 份。
**这些文件全部会进 zip**，评委翻三页就看得出来我们自己的材料没对齐。

**第二件，复现路径不稳。** `requirements.txt` 全是 `>=` 下限，readme 里却声称具体版本号；
仓库里没有任何流水线定义（这条**这次不补文件**，理由见第五节）。

**第三件，差异化还停留在"我们做了个界面功能"。** 可倒带是王牌，但它现在的表达方式是一页 PPT。
**如果它是一份带版本的事件契约**，别的 Agent 按五个字段发事件就能接这套回放器——
这是评委区分"做了什么"和"想清楚了什么"的地方。

数据出处和身份证一样：评委必问"票价和开放时间哪来的"，现在只能答"我整理的"。

## 二、四个判断，先说清楚

### 判断 1：只描述契约，不改造事件总线

`server/agent/events.py` 是 W1 攒下来的稳定面，132 个测试钉在上面，**一行都不改**。
这一单只新增一份 `event.schema.json` + 一条**会变红的**测试。

### 判断 2：深链只做 `?seq`，**不做 `lock`**

`player.js:37` 的 `setEvents(events, cursor)` 本来就支持带位置定位，成本很低。
但 `lock=1`（只读态、不跟随流式）要改的是 `main.js:161`（done 时无条件 `seek`）和
`main.js:169-170`（每条事件 `appendEvents` + `renderAll`）——**那是录屏正在走的热路径**。
改错一个字节就是视频重录。**这单不碰它。**

### 判断 3：数字不写死，也不写校验器

上一版我打算写个 `claims.py --check` 接进 CI。**被否了，理由是它对**：
关键词表写死在中文句子里，一次误报就卡死整条 CI，而它自己会变成新的真相源。

真正的病根不是"改漏了"，是**文档里写死了每轮都在变的数字**。所以：
**面向未来的文档不写死易变数字；快照型材料（PPT / 视频字幕）可以写死，但必须与重出时点一致。**

### 判断 4：溯源旁挂，不动那 237 条数据

给 237 条 POI 全加字段，等于为一个 5 行的抽查造 232 行"人工整理"的 diff，
而 `tests/fixtures/regression-chengdu-chongqing.json` 还钉着这批数据。
改成**旁挂一个 `provenance.json`**，数据文件零改动。

> 底线不变：**不许编。** 不许批量写同一个 source、不许写假 URL、
> 不许出现"官方数据"这种追溯不了的措辞。我宁可写"人工整理、未逐条核对"。

### 任务 A · 事件契约协议化

新建 `server/agent/event.schema.json`，把 `Event` 的字段固化成契约：

| 字段 | 类型 | 说明 |
|---|---|---|
| `seq` | int ≥ 1 | 实例级递增；回放器定位用 |
| `t` | number | 进程级相对时间（秒，3 位小数） |
| `type` | enum | `start` / `thought` / `tool_call` / `tool_result` / `decision` / `violation` / `fix` / `pass` / `advisory` / `unfixable` / `fallback` / `done` |
| `stage` | enum | `plan` / `validate` / `narrate` / `revise` / `system` |
| `title` | string（非空） | 回放器第一列 |
| `reason` | string | **决策依据**，回放器第二列；可空，但发了就要有意义 |
| `detail` | object | 结构化载荷（`removed` / `day` / `pois` 等） |

配 `version: "1.0.0"`。然后：

1. **校验函数用标准库写**（`jsonschema` 不在依赖里，别为这个加依赖）：字段存在性 + 枚举成员 + 类型，够用。
2. `tests/test_event_contract_schema.py`：
   - 真跑一次管线，**所有事件**通过校验
   - **造一条 `type` 非法的事件，校验必须报错**——这条证明校验不是恒真，别写只会 `return True` 的那种
3. `docs/API.md` 加**五行**（不要扩写整章）：
   > 事件契约见 `server/agent/event.schema.json`（version 1.0.0）。
   > 任何行程规划 Agent，只要按这五个字段发出事件流，就能接入本项目的可倒带回放器。

### 任务 B · 深链 `?seq`（排在 11/06 录像之后）

目标 URL：

```
/plan.html?days=3&budget=3000&tags=美食,文化&seq=17
```

要求：

- `seq=N` **隐式带上 `auto=1`**（带 seq 就是要看某一步，不该还要人再点一次开始）
- `restoreParams()`（`main.js:352`）已经是**全量**解析 URL 参数，`seq` 会自动出现在 `q` 里，
  不用改解析逻辑，只要在 `applyParams` 之后判断
- 管线跑完后定位到第 N 条：走**与手动拖进度条完全相同的路径**
  （`player.setEvents(events, cursor)` 已支持带位置，别另写一套视图逻辑）
- N 越界 → 落到最后一步，并在状态行如实提示「超出范围，已定位到最后一步」
- 定位后 `history.replaceState` 写回 cursor（拖动时同步更新，但**不要 pushState**，
  否则用户按返回键会连退 17 次）
- `home.js` 的参数透传要带上 `seq`（它用 `new URLSearchParams(location.search)` 全量读，
  大概率不用改，确认一下）

**不做 `lock=1`**（理由见判断 2）。
