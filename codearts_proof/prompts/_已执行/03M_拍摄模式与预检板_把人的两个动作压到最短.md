## 一、先说清楚这单为什么不是"杂活"

昨天我翻了五份文档核对数字，其中三个数字已经又漂了。但真正让我坐不住的不是这个。

是这件事：**距离截止还有六天，而三件必须有的东西全是零**——
视频 0 个 mp4、产品截图 0 张、公网地址 0 条证据。`package.py` 又是三道串联闸，
所以现在不是"差一点就能交"，是**差一串串行依赖**。

那三件都是人做的，码道替不了。但码道能做另一件事：
**把"人去操作界面、找准状态"这件事的成本，压到接近零。**

算一下就明白值不值：

- 六张图，规格里每张都要"展开抽屉 / 拖到中段 / 发一句话 / 悬停出 tooltip"。
  手工做，每张 3–5 分钟，中间还要确认"我这张和上一张是同一次运行"。
- 三分钟视频九镜，任何一镜状态不对就得重来，而重来一次要重新等动效、重新布场景。

所以这单的产出是两样东西：

1. **拍摄模式**：六个 URL，打开就到状态，人只需要按截图键/开始录制。
2. **预检板**：一条命令，把"现在能不能交"打成一张红绿表——最后六天每天都要用。

**这单不加任何业务功能，不改一个像素的视觉。** 它唯一的目的，是让剩下六天里
那个人（我）少做重复动作、少犯"截图和视频不是同一次运行"这种错。

## 二、四个判断，先说清楚

### 判断 1：拍摄模式只走 URL 参数，不新增 UI

六个状态全部复用现有函数：`run()`、`state.player.seek(n)`、`document.body.classList.add("drawer-open")`、
`revise()`。**不许新写视图逻辑，不许加按钮、不许加样式。**

理由很硬：**任何视觉变化都意味着视频和截图全部重来**。这一单必须做到"加了参数，
画面和现在一模一样"——只是它自己会停在某个状态。

### 判断 2：不许为截图去改地图

规格里 `map.png` 要求"悬停出 tooltip"。但 **hover 态没法用 URL 稳定复现**，
为它去改 `map.js` 会碰核心可视化，不值。

做法：`shot=map` 只负责把地图滚到视口内并让点位全部点亮；**tooltip 由人手悬停 1 秒再截**，
并在 `docs/images/README.md` 里如实写一句「tooltip 需人工悬停，其余状态由 `?shot=map` 预置」。

### 判断 3：预检板要有"人话"，不要只给退出码

这东西我每天早上会用一次。它必须回答的是「**我现在还差什么、下一步该干嘛**」，
而不是「exit 1」。每一行都要带一句能指导动作的话，比如：
「video/ 无 mp4 —— 先录；录制用 `/plan.html?shot=overview` 起手」。

### 判断 4：版本号与数字，一处真相

版本号现在有仨：CHANGELOG 顶条 1.4.2、提交清单的打包命令 1.4.1、PPT 封面写死的 v1.0。
**PPT 封面那个最刺眼**——评委先看 PPT，再解压看到 zip 名字，两个版本号对不上。

所以：`gen_ppt.py` 的版本改成读 CHANGELOG 顶条，**不只改 PPT，是把"手写版本号"这个动作删掉**。

## 三、具体做什么

### 任务 A · 拍摄模式（`?shot=`）

在 `plan.html` 上支持一个 `shot` 参数，**全部隐式 `auto=1`**，各自在管线跑完后进入指定状态：

| `?shot=` | 到位状态 | 对应截图 |
|---|---|---|
| `overview` | 跑完 → 抽屉关闭 → 选中 Day 1 → 滚动到页面顶部 | `overview.png` |
| `map` | 跑完 → 滚动到地图区 → 全部点位点亮（路线已画出） | `map.png`（tooltip 人工悬停） |
| `player` | 跑完 → 展开抽屉 → 滚动到抽屉里的事件列表 | `player.png` |
| `replay` | 跑完 → 展开抽屉 → 定位到中段（**约 60% 处最近的一条 `decision` 事件**）→ `.evt.cur` 焦点落在那条上 → 地图同步点亮 | `replay.png` |
| `chat` | 跑完 → 按真实路径发一次「第二天太赶」（走 `revise()`，不许伪造第二幕）→ 展开抽屉 → 读到第二幕 | `chat.png` |
| `budget` | 预置 **预算 900** 跑完（镜 11 的违规修复场景） | 录屏镜 11 |

实现要求：

- 统一入口：`boot()` 里解析 `q.shot`，跑完后调用一个 `applyShot(name)`。
  **`seq` 优先于 `shot`**（两个都带时按 `seq` 走，`shot` 忽略，并在控制台说明）。
- `replay` 用**与 `?seq=` 完全相同的那条路径**（`state.player.seek(n)`，n = 该事件 seq），
  别另写一套。挑事件规则：从 `events` 里取 `type === "decision"` 且 seq ≥ 总条数 50% 的第一条；
  找不到就退到最后一条 decision。
- `chat` 必须真的点一次（`$("btn-send").click()` 或走同一个 revise 入口），
  **不许把第二幕事件直接塞进 state**——那样截出来的是假画面，评委一点就穿帮。
- 到位后只在 `<html data-shot="replay">` 上做标记，**界面上不显示任何提示文字**
  （它会进截图）。需要确认到位时，我开控制台看 `document.documentElement.dataset.shot`。
- **不动 CSS**。`docs/images/README.md` 只允许加"tooltip 需人工悬停"那一句说明。

验收：

- 六个 URL 逐个打开，**不需要任何鼠标操作**就能截图（`map` 的 tooltip 除外）
- 六张图的画面与 `docs/images/README.md` 规格逐条对得上
- `shot=chat` 出来的第二幕，与手工发「第二天太赶」得到的结果一致
- `?seq=17` 的既有行为零变化（回归）

### 任务 C · 部署验证脚本（先于 B 做，因为地址一到就要用）

新建 `scripts/verify_deploy.py`：

```
python scripts/verify_deploy.py http://<公网IP>:8000
```

依次打五件事，每件打印：状态码 / 耗时 / 一个关键字段：

1. `GET /api/health` → `mode`（offline 或 online，如实显示）
2. `GET /api/meta` → 城市数、POI 总数（应为 15 城 237 点）
3. `GET /api/geo` → 点数
4. `GET /plan.html` → 200
5. `POST /api/plan {"days":3,"budget":3000,"tags":["美食","文化"]}` → 行程天数、事件条数

要求：

- **只读**，不写任何缓存、不改服务端状态
- 超时 5 秒；失败时给三条最可能原因，按顺序：安全组没放行 8000 / 起来的是多 worker
  （`/api/revise` 会 404）/ 依赖没装全
- 末尾打印一行建议存档名，例如：
  `建议存档：codearts_proof/06-一键安装与部署验证/04-公网部署-health与meta实测.png`
- 退出码：全过 0，任一失败 1

### 任务 B · 预检板（`python scripts/ctl.py preflight`）

新建 `scripts/preflight.py`，输出一张表，每行 `✅/❌ + 项目 + 一句人话`：

| 检查项 | 判据 | 不过时说什么 |
|---|---|---|
| 视频 | `video/` 有 mp4，且**时长 ≤ 190 秒** | 「video/ 无 mp4 —— 先录；起手用 `/plan.html?shot=overview`」 |
| 六张图 | `docs/images/` 里规格表列出的六个文件都存在且 ≥ 100KB | 「缺 chat.png —— 用 `/plan.html?shot=chat` 打开直接截」 |
| PPT 常量 | `gen_ppt.py` 的 `SUBMIT_DATE`、`DEMO_URL` 不含下划线 | 「DEMO_URL 还空着 —— 地址拿到后填进去再重出 PPT」 |
| 演示地址可达 | 3 秒内 `/api/health` 返回 200 且含 `mode` | 「公网地址打不开 —— 先确认安全组放行 8000」 |
| 占位残留 | 复用 `check_placeholders` 的函数（**别重写**） | 「staging 里还有 ______ 未填」 |
| 任务单份数 | ≥ `package.py` 里 `need_prompts` 的项数 | 「少归档了 03M」 |
| 版本号一致 | CHANGELOG 顶条 / `gen_ppt.VERSION` / `提交清单.md` 里的 `--version` 三处相同 | 「三处版本号不一致：1.4.2 / 1.4.1 / v1.0」 |

细节：

- **mp4 时长用标准库解析**，不要引入 ffprobe 依赖。做法：读文件前 2MB，找 `b"mvhd"`，
  跳过 4 字节（version + flags）后：
  - version 0：`creation(4) modification(4) timescale(4) duration(4)`
  - version 1：`creation(8) modification(8) timescale(4) duration(8)`
  时长 = duration / timescale。解析失败时**如实说"读不出时长"并降级为 ⚠️**，不要假装通过。
- 六个图片文件名**从 `docs/images/README.md` 的表格里解析**，不要硬编码第二份清单。
- `--offline` 参数跳过"地址可达"那一项（没有网络时也能用）。
- 接进 `ctl.py`：`python scripts/ctl.py preflight`。

## 四、验收标准

**A 拍摄模式**

- 六个 URL 逐个打开：无需鼠标操作即可截图（`map` 的 tooltip 除外，已在 README 如实标注）
- 六张图与 `docs/images/README.md` 规格逐条对得上
- `shot=chat` 的第二幕是真实 `revise()` 产物（对比手工发同一句的结果，事件一致）
- 同时带 `seq` 与 `shot` → 走 `seq`，并在控制台说明
- `?seq=17` 行为零变化
- **CSS 零改动**（`git diff static/style.css` 为空）

**B 预检板**

- 一条命令出表，七项齐全，每项都有人话
- 现在跑：视频 ❌、六图 ❌、DEMO_URL ❌、地址 ❌ —— **这就是它该有的样子**
- 故意把一张图删掉 → 对应行变 ❌ 并指出缺哪个文件
- 故意把 mp4 时长参数改成 300 秒的样本 → 报"超 3 分钟"
- 读不出时长时给 ⚠️ 并说明原因，不冒充通过

**C 部署验证**

- 本地 `python -m uvicorn server.app:app --port 8000` 起服务后跑一遍，五项全 ✅
- 打到不存在的端口 → 五项失败但**给出三条可能原因**，退出码 1
- 输出可以直接截图存档（列宽不串行、无颜色转义符污染）

**D 口径**

- 五处改完；全仓再搜 `139`、`23 步`、`v1.0`，除 CHANGELOG 与任务单原文外应无命中
- `gen_ppt.py` 的 `VERSION` 能跟着 CHANGELOG 走（改 CHANGELOG 顶条版本号 → 封面随之变）

**E 打包闸**

- 删一张图 → `package.py` 失败并点名缺哪个文件
- mp4 超长 → 失败并打印实际时长

**回归**

- `python scripts/ctl.py ci` 三连全绿；现有 156 个用例**一个都不许删**
- 默认场景行程与 `tests/fixtures/regression-chengdu-chongqing.json` 逐字一致
- 断网保命不破：后端不起，前端仍能完整演示（拍摄模式在 Mock 下同样可用）
