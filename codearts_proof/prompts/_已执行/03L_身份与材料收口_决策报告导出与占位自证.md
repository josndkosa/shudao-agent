## 二、四个判断，先说清楚

### 判断 1：身份信息只能有一个来源

队名会出现 5 处：`gen_ppt.py` 封面 + 尾页、`package.py --team`（→ zip 文件名）、
`readme/团队分工.md`、`readme/README.md`。四处手工维护 = 下次又对不上。
→ **在 `gen_ppt.py` 顶部建一个常量块，全部从那里取。**

### 判断 2：占位检查必须能穿透 pptx

`ppt/蜀道智行.pptx` 本身是 zip，文字存在 `ppt/slides/slideN.xml` 里。
直接对二进制 grep 找不到——要把它当 zip 解开查 `ppt/slides/*.xml` 与 `ppt/notesSlides/*.xml`。

### 判断 3：报告渲染**必须解包 detail**，否则第 4 节会静默空白

`docs/API.md`「事件 detail 字段的确切形状」已经写死：

| 调用写法 | detail 形状 | 典型事件 |
|---|---|---|
| `emit(..., detail=X)` | **嵌套** `{"detail": X}` | 选点 decision、**violation**、**advisory**、tool_result 的 detail 参数 |
| `emit(..., 具名键=值)` | 扁平 `{k: v}` | fix（`{violation, removed}`）、tool_call、tool_result(count)、start(mode) |

前端唯一解包入口是 `static/js/view.js:22-25` 的 `payload(ev)`（自动解一层内层 `detail`）。

**后果**：报告第 4 节要写 violation / advisory / unfixable，**这些恰好是嵌套形状**。
渲染器如果直读 `ev.detail.rule`，拿到的是 `undefined` → 第 4 节只剩标题没有内容 →
而"六节结构齐全"这条验收**照样通过**。
这正是 03H 任务 H5 那次 P0（`map.js` 各读各的层级、路线从未渲染过）的重演。
→ **后端必须写一个与 `payload(ev)` 语义等价的解包函数，两边规则必须完全一致。**

### 判断 4：报告的价值在"下载下来的那个文件"，不在"多一个按钮"

所以：六节结构固定、`reason` **全量不截断**、**断网（Mock）也能导出**且与在线版结构同构、
**不做 PDF**（中文字体渲染是运维坑，Markdown 交给浏览器打印，一句话就能解释）。

- 事件契约版本从 `server/agent/event.schema.json` 的 `version` 字段**读出来**（该文件会随 `server/` 一起进 zip，运行时可读）——**不许再手抄一份**。
- 生成时间用**真实时间**，不要写死。

**解包 detail（判断 3，这是本节最容易翻车的地方）**：

```python
def unwrap_detail(ev: dict) -> dict:
    """与前端 static/js/view.js 的 payload(ev) 语义等价：
    detail 是 object 且含 'detail' 键 → 取内层；否则原样返回。
    规则必须与前端逐字一致，改一处改两处。"""
```

- **不许直读 `ev.detail`**（直读会拿到嵌套外壳）
- 有测试锁：造一条**嵌套**事件（`{"detail": {...}}`）和一条**扁平**事件（`{"violation": ..., "removed": [...]}`），
  两条都要解出正确载荷
- 报告第 4 节的「被移除点 ID」取自 `fix` 事件的**扁平** `detail.removed`；
  「违规详情」取自 `violation`/`advisory` 事件的**嵌套**内层。两种形状都要出现在报告里。
