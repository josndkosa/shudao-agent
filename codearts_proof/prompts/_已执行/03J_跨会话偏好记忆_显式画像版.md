# 给码道的下一条任务单：跨会话的偏好记忆（显式画像版）

> 这条整段粘给码道（IDE 模式）。
>
> ⏰ **执行时序：排在初筛提交完成之后（约 11/16 之后），答辩（11/21–11/27）之前。**
> 理由很实在：**初筛是评委解压 zip 看材料，他没法真跟我们的产品聊两轮验证它记不记得。**
> 这个功能的价值在**答辩现场能演示** —— 说一次、刷新页面、再说一次，它自动带上上次的偏好。
> 初筛阶段不要动它，免得挤占提交链、动了界面还要重拍截图。
>
> 前置：03G（自然语言规划入口）已完成、03I（前端三修）已完成。

---

## 一、这个功能要解决什么

评委问 Agent 类项目时，**「有长期记忆吗」是高频问题**，现在我们的答案是"没有"。

我们要做的是**最低成本、但诚实且能演示**的那个版本：**显式偏好画像**。

用户主动说「记住：我不去博物馆」→ 我们记下来 → **下一次规划自动带上**。

演示时是这样：

> 第一次："记住：我带娃，不去博物馆"
> 第二次："去大理玩三天" → "已按上次的偏好规划：亲子模式 + 避开博物馆"

**这就是「个性化」在行程规划里的最小完整形态。**

---

## 二、三个设计决定，先说清楚

### 决定 1：显式指令式，不要黑盒画像

**不做**「用户说带娃 → 我们偷偷推断他偏好亲子 → 自动记下」这种画像式记忆。

理由是**信任**：记忆是"我们替你记住了什么"，用户必须**知道**、**能改**、**能删**。
黑盒画像在演示里说不清、在答辩里答不好、在产品里也让人不安。

所以记忆只通过**明确的指令**触发：

| 说法 | 归一化成 |
|---|---|
| 「记住：我带娃」 / 「记住：带 5 岁小孩」 | `family = true` |
| 「记住：预算两千」 | `budget = 2000` |
| 「记住：喜欢夜景」 | `tags` 里加「夜景」 |
| 「记住：不去博物馆」 | `avoid_tags` 里加「博物馆」 |
| 「记住：不吃辣」 | **记不了** → 如实提示 |

「记住」「别忘了」「记一下」「帮我记住」都识别成触发词。

### 决定 2：零 UI 改动

**不加"记住我的偏好"开关、不加设置面板。** 全部通过对话栏操作。

原因很硬：**加 UI 就得重拍产品截图、重做 PPT**。我们初筛材料已经定稿，
不值得为一个开关破掉它。

而且**用自然语言说"记住：xxx"比点开关更自然** —— 它跟 03G 做的自然语言入口是一套东西，
用户不用学新交互。

### 决定 3：偏好记忆存在用户主目录，**不进仓库、不进提交包**

路径：`Path.home() / ".shudao" / "preferences.json"`（Windows 是 `%USERPROFILE%\.shudao\`）。

**为什么不能放 `server/data/`**：那会被 `scripts/package.py` 打进提交包的 `project/` 里，
**等于把某个用户的个性化数据分发给所有评委** —— 隐私问题，也很不专业。

环境变量 `SD_PREFERENCES_PATH` 可以覆盖路径（测试用）。

## 三、诚实边界：这一版能记什么、不能记什么

**必须写进代码注释、`docs/开发指南.md` 和 PPT 的说明里。**

| 能记 | 怎么生效 |
|---|---|
| 亲子模式 | `family=true` → V5 规则筛掉亲子友好度 < 2 的点 |
| 预算 | 覆盖请求里的 `budget` |
| 喜欢的标签 | 合并进 `tags` → 偏好打分加权 |
| 排斥的标签 | 新增 `avoid_tags` → **选点阶段排除**（不靠打分，是硬排除） |

**不能记的（数据层没有这个维度）：**

- **口味偏好**（「不吃辣」「不吃牛羊肉」）
- 具体的某个景点名
- 酒店、航班偏好
- 任何 POI 数据里没有的字段

遇到记不了的（比如"不吃辣"），**如实告诉用户**：

> 「记住了亲子模式和预算。口味偏好这块，当前快照的数据维度还不支持，先记不下来。」

**不要说"记住了"然后默默丢掉** —— 那是欺骗。

## 四、具体做什么

### 任务 A · 偏好文件

新建 `server/agent/preferences.py`：

```python
def load_prefs(path=None) -> dict:
    """读偏好画像；文件不存在/损坏/读不了 → 返回空画像，绝不抛异常。"""

def save_prefs(prefs: dict, path=None) -> bool:
    """写偏好画像；写失败 → 返回 False，不影响主流程。"""

def merge_prefs(base: dict, prefs: dict) -> tuple[dict, list[str]]:
    """把记忆合并进本次请求参数。
    返回 (合并后的参数, 应用了哪些记忆的说明列表)。
    显式指定的值优先于记忆（例如用户这次明确说了预算 5000，就用这次的）。"""
```

文件结构（`~/.shudao/preferences.json`）：

```json
{
  "version": 1,
  "updated_at": "2026-11-20T10:00:00",
  "prefs": {
    "family": true,
    "budget": 2000,
    "tags": ["夜景"],
    "avoid_tags": ["博物馆"]
  }
}
```

**写文件要考虑**：目录不存在要建、原子写（先写临时文件再 rename，避免写一半断电）、
文件损坏时 JSON 解析失败要**降级为空画像而不是崩**。

### 任务 B · 抽取器扩展（03G 的 `parse_request` 上加一层）

`parse_request` 现在的返回值里加两个字段：

- `remember`: bool —— 这句话是不是在要求"记住"
- `forget`: bool —— 这句话是不是在要求"忘掉"

**识别触发词**：
- 记住类：「记住」「别忘了」「记一下」「帮我记住」「以后都」
- 忘掉类：「忘掉」「别记了」「忘记我的偏好」「清空我的偏好」

**从同一句话里把偏好内容抽出来**（复用 03G 已有的抽取逻辑：天数、预算、标签、亲子、别名映射）：
- 「记住：我带娃，不去博物馆」 → `{family: true, avoid_tags: ["博物馆"]}`

**如果这句话里没有可记的内容**（「记住：我不吃辣」）→ `remember=true` 但抽不出偏好 →
**如实提示，不要记一个空画像**。

### 任务 C · 记忆的读写时机

**记住的时候**：抽取器判断出 `remember=true` 且抽到了偏好 →
写文件 → **发事件**（stage=`system`）说明记了什么。

**忘掉的时候**：清空（或只删指定项）→ 发事件说明忘了什么。

**规划的时候**（`run_pipeline` 或 `planner.offline_plan` 入口）：
读偏好 → `merge_prefs` 合并进 `TripRequest` → **发事件**说明本次应用了哪些记忆。

⚠️ **合并时的优先级**：**用户这次明确说的值优先于记忆。**
用户上次说"预算两千"、这次说"预算五千"，用五千。

**没有记忆文件、文件损坏、读不了 —— 全部静默降级成"无记忆"，绝不影响主流程。**
断网保命这条不能破。

### 任务 D · `avoid_tags` 的生效方式

这是唯一需要碰选点逻辑的地方，请**小心**：

- `avoid_tags` 是**硬排除**，不是打分扣分 —— 命中就直接不进候选
- 只在**候选筛选**那一步生效（在 `poi_search` 之后、打分装箱之前）
- **不影响 V1–V5 的任何判定逻辑**
- 空列表时行为与现在**完全一致**

**建议加一条测试**：一个带 `avoid_tags: ["博物馆"]` 的请求，结果里不含任何博物馆类 POI；
一个不带 `avoid_tags` 的请求，结果与改造前**逐字一致**。

### 任务 E · 用户能看、能删

两个自然语言指令（不加 UI）：

- **「我记住了什么」/「看看我的偏好」** → 回一条消息，列出当前画像
- **「忘掉我的偏好」/「清空我的偏好」** → 清空并确认

这两个走对话栏，跟 03G 的入口是同一套。

## 五、事件流里必须能看到"记忆生效了"

**这是这个功能能不能被验证的关键。**

规划时如果应用了记忆，事件流里要有一条看得见的事件，比如：

```
#012 [system] ⚙ 应用偏好记忆
     └ 因为 记得：你带娃 / 避开 博物馆（上次记录于 2026-11-20）
```

**没有这条事件，评委在回放器里就看不到记忆起作用了**，
答辩时也只能靠嘴说 —— 那等于没有证据。

事件 reason 里要写清：**记住了什么、什么时候记的**。

## 六、验收标准

**记忆读写**

- 「记住：我带娃，不去博物馆」→ 偏好文件里出现 `{family: true, avoid_tags: ["博物馆"]}`
- 「记住：预算两千」→ `budget: 2000`
- **「记住：我不吃辣」→ 如实提示记不了**，且**偏好文件里没有多出任何东西**
- 「我记住了什么」→ 能列出当前画像
- 「忘掉我的偏好」→ 文件清空并确认
- 偏好文件**不存在时**读偏好 → 返回空画像，**不报错**
- 偏好文件**内容损坏时**（故意写个非法 JSON）→ 降级为空画像，**不报错**
- 偏好文件**所在目录不可写时** → 保存失败但**规划照常跑完**

**生效**

- 记住「带娃」之后规划 → 行程里**没有**亲子友好度 < 2 的点（V5 生效）
- 记住「不去博物馆」之后规划 → 行程里**没有**博物馆类 POI
- **不带记忆的请求 → 输出与改造前逐字一致**（回归锁）
- **显式指定优先于记忆**：「上次说预算两千，这次说预算五千」→ 用五千

**可观察**

- 规划时应用了记忆 → **事件流里有「应用偏好记忆」那条事件**，reason 写明记住了什么
- 记住的瞬间 → 事件流里有「已记住」那条事件
- 忘掉的瞬间 → 事件流里有「已忘掉」那条事件

**回归**

- `python scripts/ctl.py ci` 三连全绿，pytest 至少 **96 个**（03I 之后 ≥92，加上本轮新增）
- **离线模式完全不受影响** —— 记忆功能在离线和在线下都要能用（它不依赖 LLM）
- 冒烟至少 18 步

**隐私**

- 偏好文件**在用户主目录**，**不在仓库里、不在提交包里**
- `git status` 里看不到偏好文件
- `docs/开发指南.md` 写清楚：偏好存在哪、怎么删、它**不随作品分发**

## 七、有几件事别做

- **别加 UI**（开关、面板、设置页一律不要）。这是硬约束 —— 加了 UI 就要重拍截图。
- **别做向量检索 / embedding / 语义相似度记忆。** 成本高、要 embedding 服务，
  而且在初筛这个时间点上纯属浪费。**这一版就是"显式偏好画像"，被问到就这么说。**
- **别做黑盒画像推断**（用户没说就自己记）。只记明确说出来的。
- **别让记忆影响校验段的任何判定**。`avoid_tags` 只在候选筛选阶段生效。
- **别让偏好文件进 `server/data/`**，那会被打进提交包。
- **别在偏好里存任何敏感信息**（身份证、联系方式、精确住址）。
  我们只记「亲子/预算/标签」这种粗粒度偏好。
- 别引新依赖（标准库 `json` / `pathlib` / `os` 够了）。
