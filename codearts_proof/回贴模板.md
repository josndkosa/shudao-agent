# 协作闭环协议（你 ↔ 码道 ↔ 我）

三方分工固定：**我出可粘贴的建议 → 你粘贴给码道 → 码道实现 → 你把结果贴回给我 → 我验收并给下一条建议。**

---

## 一、粘贴协议

1. 打开 `codearts_proof/prompts/NN_*.md`
2. **整段复制全文**（从第一行到最后一行的所有内容，包括"背景""硬约束""交付要求"）粘给码道
   - 码道看不到我们的对话，**上下文必须全部在这条 prompt 里**，所以不要删减、不要"你懂的"
   - 需要他读的文件路径是**相对于项目根目录**的，粘之前确认当前工作目录是 `D:\项目代码\shudao-agent`
3. 码道执行完，把他的回复**贴回给我**（按下面的模板）
4. 我按 `ACCEPTANCE.md` 逐条验收，给出「通过 / 打回 + 具体修改建议」，通过后给下一条 prompt

## 二、回贴模板（每次复制这段发给码道，把回复填进来）

```
【prompt 编号】NN
【码道回复原文】
（把码道的完整回复粘贴在这里，不要删减）

【命令真实输出】
$ python -m pytest -q
<粘贴完整输出>

$ python cli.py --days 3 --budget 3000 --tags 美食,文化
<粘贴完整输出>

【改动的文件清单】
<粘贴码道列出的文件列表>

【码道自己的疑问/未完成项】
<粘贴；没有就写"无">
```

## 三、执行顺序

| 顺序 | Prompt | 为什么是这个顺序 |
|---|---|---|
| 1 | `00_基线自检与素材一次性产出` | 在**缺陷未修**的代码上跑一次，固化 **before 快照** + 缺陷复现证据 + 公共素材（依赖清单/架构图/真实 demo） |
| 2 | `01_修复W1缺陷_P0` | 缺陷直接扣"功能完备度 30 分"，且 D1 已在实战输出中伤到主线行程。修完 demo 数据才可信 |
| 3 | **`03_W2前端_单页SVG路线图_可倒带时间轴`** | **前端先行**：本次最贵的两样都在前端——可倒带时间轴的交互设计、双城 SVG 版面。早出实物早迭代。mock 数据来自修复后的 `cli.py --json` **真实产物**，不必等后端 |
| 4 | `02_W2后端_FastAPI_SSE_对话改行程` | **照前端已固化的 `static/js/api.js` 契约实现**，接上后前端零改动切换 |
| 5 | `04_readme_一键安装_工程整理` | 交付规范 5 分 + 码道"文档生成"覆盖度 |
| 6 | `05_PPT与视频分镜_走码道Space模式` | **走 Space 模式**，直接命中码道"文档生成"覆盖度 |

> **00 与 03 的数据分工**：
> `docs/baseline/baseline-demo.json` = **修复前**（before），用于 before/after 对照与 PPT 的调试排错章节；
> `static/demo.json` = **修复后**（after），由 03 的 `export_demo_assets.py` 重新生成，才是前端真正用的数据。
> 两者**不可混用**。

## 六、我的输出约定（方便你直接复制）

我之后给你的每一份建议都会是**整段可复制的 markdown**，并且：

- **自带完整上下文**——码道看不到我们的对话，不会出现"如上所述"
- **含硬约束与验收标准**——码道能自检，你也能自检
- **需要你手填的内容一律用 `______` 占位**——我不会替你编造专业、队名、联系方式
- **风险与假设显式声明**——符合 `karpathy-guidelines` 的"声明假设 → 最少改动 → 行级可追溯需求 → 可验证成功标准"

我不会替码道写生产代码，也不会替你做只有你能做的决定（专业、队名、真实信息）。
