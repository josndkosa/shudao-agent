## 任务单写法本身也演进了一轮（这是 Prompt 工程的一部分）

早期任务单（00–04）是**规格表体**：`硬约束 → 逐条任务 → 验收标准 → 禁止`，
像一份需求文档。后来（03F 之后）改成了**对话体**：先说清「为什么要做这件事」、
当时的现场是什么、哪些是我已经确认过的判断，再给具体要求。

**这不是风格偏好，是有实际收益的**：

| | 规格表体 | 对话体 |
|---|---|---|
| 传达意图 | 只说"做什么" | 说清"为什么"，AI 不用猜意图 |
| 保留上下文 | 一次性要求，返工就重写 | 记录了当时的判断依据，返工能接上 |
| 验收 | 靠人肉核对 | 仍是硬指标，但**理由也传下去了**，AI 知道边界在哪 |

一次典型的例子：03F 任务 A 之所以能一次做对，是因为任务单里写明了
「`_poi_brief` 写了但**从未被接上**」这个细节 —— 这不是需求，是**上下文**。
如果只说"工具结果要精简"，AI 大概率会重新写一个精简函数，而不是去把那个早就写好的接上。

**风格演进本身就是「码道深度使用」里"Prompt 设计质量"那一格的素材**：
它证明我们不是一次性写了个 prompt 模板，而是**在真实返工里持续改进任务单的组织方式**。

⚠️ 已归档的早期任务单（`_已执行/` 里的 14 份）**保持原样不动** ——
它们是"当时实际粘贴给码道的原文"，也是 `codearts_proof/` 里的证据。
证据与说明文档的区别就在这儿：说明文档会更新，证据不改。

## 每轮一句话决策（被人工评审推动的返工加粗）

- **00**：先测量后动手——baseline 是 before/after 对照的锚
- **01**：V1 的城际 1.8h 在 span 加了在 cap 没扣 → 阈值被压到 20:13 → 修磁器口/湖广会馆被误删
- **01B**：**软约束不该占硬违规的名额**——V3 不删点是正确的产品判断，空转是循环设计错
- **01C**：**「因为坡陡所以不看夜景」是荒谬的**——强度惩罚豁免必游与夜间点；排序键写反是潜伏 bug 的教科书案例（现有测试 _score 互异，次级键从未被比较）
- **02**：SSE 哨兵 bug 是 TestClient 侥幸漏过、真实端口才暴露的——检查层级每上一级能抓的 bug 多一类
- **03**：契约先行（api.js 固化六方法），后端照契约实现，前端零改动切换
- **03B**：removed 字段让「violation→fix→pass」在地图上同步可见——核心卖点的可视化补齐
- **03C**：语法检查≠运行时验证——冒烟脚本把「点开始规划才炸」变为一秒必现的回归用例
- **03D→03F**：**两次视觉方向均被人工评审否决重做**——人负责否决坏答案，码道负责实现
- **04**：反过度工程化——加骨架不加抽象层；ruff 顺带抓到 3.12 f-string 兼容性真 bug
- **03E 批次1**：双城回归用 fixture 锁死再动刀；地形分档是「同样的强度在不同海拔是另一回事」的规则参数化
- **直觉性轮**：多城化后每个旧边界都要重新问一遍——days<城数超发是缺陷 2 的多城版复发
- **双页轮**：品牌与工作台分离是演示叙事的清晰化；旧链接透传保住文档零破坏
- **字号轮**：瑞士网格靠比例不靠像素绝对值，等比放大不破坏版式；空态写了但没挂载=没写
- **Day tab 轮**：对象展开顺序是隐式状态覆盖的高发区——后展开的键会吃掉前面的
- **P0 复核轮**：**冒烟脚本用「与 bug 一模一样的错误表达式」手工造数据，是虚假安全感的教科书案例**——事件流→视图状态这条链路必须用真实产物跑且有断言
- **在线接入轮**：`.env.example` 与 `.env` 是天然陷阱（接入文档要写「复制」不是「参考」）；git-bash 的 `taskkill /F` 会被 MSYS 静默转义——每步无报错结论却错时，先确认「我 curl 到的真是刚起的进程」
- **幻觉治理轮**：**残缺 JSON 会被模型「补全」成幻觉**——五城工具结果 5624–8024 字符全超 4000 截断线，每城必烂不是偶发；`_poi_brief` 写了从未被调用（检查工具函数是否真的被调用）
- **收口轮**：四层数据口径不一致本身就是幻觉温床（meta 承诺的城市查不到 → 模型只能编）；离线测试永远测不到「模型补全残缺 JSON」这类缺陷——两条路都要跑
- **03G 轮**：抽取与规划分离——参数抽取结果**可见可改**地回填表单，比一句黑盒直答更可信；「我在北京」的出发地如实标注「暂未计入」，不假装算了
- **03I 轮**：能被人真实使用 30 天后挑出的三个毛病，比任何测试用例都真——「真跑起来了」本身是材料
- **03J 轮**：「有长期记忆吗」的诚实答案——只做显式指令式记忆（记住/忘掉/查看），不做黑盒画像推断；记不了的就明说记不了，画像零污染
- **05 轮**：PPT 数字全部实测口径、占位如实待补——答辩材料宁可写「待补录」也不画假界面
- **03K 轮**：回放不是界面功能，是**带版本号的决策事件契约**（别的 Agent 按五个字段发事件就能接）；文档不写死会过期的数字——快照型材料（PPT）改为重出时现读实测；顺手修掉的两个既有 bug（Mock 双跑、done 误吞）说明「同构」不是写了就算的，要跑出来对
- **03L 轮**：报告的价值在「下载下来的那个文件」，不在「多一个按钮」——六节固定、reason 全量、断网同构、不做 PDF；**PPT 上的身份信息只能有一个来源**（常量块，五处取用），队名与平台报名一字不差；「Repo 托管」这类不成立的陈述比没有更糟；占位残留要变成打包时必红的闸（pptx 是 zip，横杠藏在 slides 的 XML 里，得穿透扫）
- **审查修复轮（外部报告）**：**先独立复现再修，不盲信任何单一审查方**——五个 P0 全部本地复现后才动手，每条配回归锁；正确性修复可以接受 baseline 漂移（餐点重叠是错的，时刻后移是对的，fixture 注明重生成原因）；测试全绿不等于用户流程正确（146 个测试钉着的时候，武侯祠和午餐照样重叠着过了两轮材料）
