# 开发指南

> 三条「如何扩展」路径，每条都点到具体文件与测试——新增能力不动架构。

## 〇、偏好记忆：存在哪、怎么删、不随作品分发（03J 必读）

「长期记忆」采用**显式偏好画像**——用户说「记住：我带娃，不去博物馆」才记，
不做黑盒画像推断（记忆必须用户知道、能改、能删）。

- **存储位置**：用户主目录 `~/.shudao/preferences.json`
  （Windows：`%USERPROFILE%\.shudao\`；`SD_PREFERENCES_PATH` 环境变量可覆盖）。
  **它在仓库和提交包之外**——`server/data/` 会被 `scripts/package.py` 打进 zip
  分发给评委，用户个性化数据绝不能放那
- **怎么删**：对话栏说「忘掉我的偏好」全清，或「忘掉博物馆」删指定项；
  也可以直接删文件（删了 = 无记忆，规划照常）
- **能记什么**：亲子模式（→V5 生效）/ 预算（填自然语言未说的空缺，显式值优先）/
  喜欢的标签（合并打分）/ 排斥的标签（`avoid_tags`，候选筛选阶段硬排除，不碰 V1–V5）
- **记不了什么**（数据层没有该维度，遇到如实提示）：口味偏好（不吃辣）、
  具体景点名、酒店/航班偏好——绝不假装记住
- **容错**：文件不存在/损坏/目录不可写 → 一律静默降级为无记忆（原子写防半文件）；
  记忆操作纯规则实现，**不依赖 LLM**，离线在线都能用
- 实现见 `server/agent/preferences.py`（读写合并）与 `parse_request.py`（意图识别），
  测试 `tests/test_preferences.py`；演示后清理本机画像：说「忘掉我的偏好」即可

## 〇.五、数据规模约束（03G：天数上限放开后必读）

**一个城市每天消耗 3–5 个点位（贪心装箱容量约 11h），单城能撑几天由它的 POI 密度决定**：
成都 22 点约 4–7 天、多数广度层城市 15 点约 3–4 天。天数上限已放开到 30，
但**放开上限 ≠ 任何天数都排得出来**：

- 某城候选点用尽 → 该天不安排、不占 day 序号，并**发 `plan/fallback` 事件**如实说明
  （「XX 候选点已用尽，无法安排第 N 天……建议多选城市」）
- 预算按**实际行程天数**核算（餐饮/市内交通/日均，planner 与 validator 同口径），
  不按请求天数——被截断时不会系统性低估日均
- 前端 `p-days` 附近有常驻提示「单城约撑 4–5 天，天数多建议多选城市」
- 想稳定排出 12+ 天：显式勾选 8–10 个城市（西南 15 城 POI 总量 237 点）

## 一、如何新增一个城市（例：贵阳）

1. **建分城快照** `server/data/<城市拼音>.json`：从 `chengdu.json` 复制结构，
   按字段规范（`server/data/schema.md`）填 15–25 个点
2. **改 meta.json**（`server/data/meta.json`）：
   - `cities` 数组加城市名
   - `city_info` 加省份/天气/terrain 分档（V3 强度阈值）/图幅注记行
   - `city_hub` 加枢纽坐标（城际自动生成以枢纽球面距离为默认值）
   - `intercity_rail` 按需加人工覆盖线（如 `"成都-重庆": {"hours": 1.8, "price": 154}`）
3. **完成——算法零改动**。`load_pois()` 按 glob 自动合并；`load_city_pois()` 扫数据文件
   的 `city` 字段**自动建索引**（03H 任务E 落地）——`tests/test_event_contract.py` 的
   `test_load_city_pois_auto_index_new_city` 守护这条「零代码改动」承诺
4. 验证：`python -X utf8 cli.py --days 4 --budget 4000 --tags 文化` 看是否出现新城天；
   `pytest -q` 的数据完整性断言是增长式的（`test_new_cities_data_integrity` 断言 ≥15 点
   与字段齐全、四集合一致锁断言 meta==文件==hub==可查），新增城市无需改测试阈值

> meta.json 的 `city_info` / `city_hub` / 数据文件 / `load_city_pois` 可查四层口径
> 必须一致（`test_four_layer_city_consistency` 锁死）——meta 承诺了却没有数据文件的城市
> 会成为 LLM 幻觉 POI 的温床（工具 schema 让模型以为可选，一调就返回空）。

## 二、如何新增一条校验规则（例：V6 雨天户外）

1. **`server/agent/validator.py`** 的 `validate()` 循环里加判定块：
   - 产出 `{"rule": "V6-rain", "severity": "hard"|"soft", "day": N, "poi": pid,
     "detail": "中文说明", "fix_hint": "drop"|"none"}`
   - **先想清楚 soft 还是 hard**（判定标准：是否存在唯一正确的自动修复——没有就 soft）
2. **若为 hard**：在 `server/agent/planner.py` 的 `fix()` 加对应分支
   （参考 V4-budget：摘高票价非必游点），并 emit `fix` 事件带 `removed=[poi_id]`
   （前端地图灰叉/行程卡删除线依赖此字段）
3. **写测试**：`tests/test_validator.py` 仿照 `test_v2_open_window_violation`
   ——构造触发场景 + 不触发场景各一个（先红后绿）
4. 文档：`docs/规则引擎规格.md` 总表加一行；若改了容量口径必须同步「不变量」一节

## 三、如何新增一个事件类型（例：`annotate` 标注）

1. **后端**：`server/agent/events.py` 的 Event.type 注释枚举加值；在管线合适位置 emit
2. **前端渲染**：
   - `static/js/player.js` 的 `TYPE_MARK` 加图标（如 `"annotate": "✎"`）
   - `static/style.css` 加 `.ty-annotate` 着色（瑞士体系下：违规系朱红、其余黑灰）
   - `static/js/main.js` 的 `applyEvent()` 若该类型影响视图状态机，加映射分支
     （不影响就无需改——reason 照常展示）
3. **契约同步**：`docs/API.md` 事件枚举表加一行
4. 验证：`node scripts/smoke_frontend.mjs`（TYPE_MARK 键名错误会立刻炸）
